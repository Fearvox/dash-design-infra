Finding 1: border-radius is format-dependent, not addressable drift

Across 12 surfaces, border-radius serves distinct creative purposes:

  • 999–9999px near-circle: avatar circles, pill badges — format signature across all families
  • 50% circular: avatar images — 7/12 surfaces (all families); cannot normalize without breaking image rendering
  • 8px subtle: 4 surfaces share this value — the only plausible token candidate (family-dna, motion-storyboard, prompt-dna-adapter, pdf-zine)
  • 22–44px large: panel/card borders — 8/12 surfaces use different values; no family consensus

No --radius-* token layer exists in any surface. Introducing one would require deciding which creative formats to homogenize — a design decision, not a mechanical normalization.

Finding 2: 8px is the only intra-family convergence point

Warm-paper surfaces: family-dna (3,6,8px), motion-storyboard (8px×4), prompt-dna (8px×2), pdf-zine (8px) all use 8px for card/panel rounding. This is the closest thing to a shared radius token — but it is not yet defined as --radius-card in any :root block.

Opportunity (low priority): define --radius-card: 8px in warm-paper :root blocks and replace hardcoded 8px values. Would require confirming all four uses are visually equivalent before replacing.

Verdict: border-radius tokenization is viable only for the subtle 8px category on warm-paper family. All other categories are format-locked and will not converge. Recommend closure as diagnostic — no surface edits.

DIAGNOSTIC No implementable surface edits. border-radius tokenization is not viable: 999-9999px near-circle and 50% circular are format-locked per surface role. 8px is the only convergent value (4 warm-paper surfaces) but introducing --radius-card requires design decision. Recommend: close as resolved diagnostic, move to next token axis.
