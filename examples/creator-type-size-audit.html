Finding 1: h1 font-size — no shared token

11 surfaces produce 10 distinct h1 sizes: 132, 76, 78, 84, 104, 44, 72, 78, 84, 88, 76. The range (44px–132px) spans editorial poster scale down to compact card scale. No surface uses a CSS custom property for type scale — all are hardcoded px in element rules.

Family grouping: warm-paper h1: 132, 76, 78, 84, 104, 44. dark-industrial: 72, 84, 76. creative-hybrid: 78, 88. No intra-family consensus.

Verdict: Type size tokenization (e.g. --type-h1: 84px) is possible but would require explicit design decision about what scale the DASH family actually targets — not just an arithmetic mean. A single consensus value would homogenize surfaces that have intentional size variation for their format (poster vs. social card vs. zine).

Finding 2: --space-4 participation — 6/11 surfaces have it

Warm-paper: poster-surface, pdf-zine, social-card, motion-storyboard, prompt-dna (5/6) have --space-4: 16px in :root and use var(--space-4) in body CSS. family-dna has --space-4 but does not use var(--space-4) in body.

Non-warm-paper: browser-demo, p5-sketch, remotion-scene, manim-scene, touchdesigner-tox — 0/5 have --space-4 in :root.

Opportunity: Add --space-4: 16px to the :root token layer of non-warm-paper surfaces as a shared spacing primitive, without changing any body px values. This would give all 11 surfaces the same spacing vocabulary to reference.

Finding 3: Font stack family DNA

Serif stack (ui-serif, Georgia, Cambria, "Times New Roman", serif): warm-paper surfaces (poster, social-card, motion-storyboard, prompt-dna, manim-scene). Sans stack (ui-sans-serif, system-ui...): dark-industrial surfaces (browser-demo, p5-sketch, remotion-scene, touchdesigner-tox). This is a family signature, not addressable drift — keep as-is.

The serif/sans split communicates the editorial warmth vs. industrial constraint contrast that defines the DASH visual grammar. Overriding it would flatten the family hierarchy.

Finding 4: Border-radius — 0 surfaces share a token

All 11 surfaces use hardcoded border-radius px values (4px–999px). No --radius-* token layer exists. Unique values range from 3 to 9999 (pill/circle shapes). Pattern: no convergence even within families.

Recommended: do not introduce a --radius-* token layer unless a specific visual inconsistency causes creator confusion. The 9999px pill shape is format-dependent (avatars, badges) and cannot be normalized.

DIAGNOSTIC No implementable surface edits found. h1 font-size tokenization requires an explicit design decision (what scale does DASH family target?) before any alignment. --space-4 extension opportunity is additive but low urgency (no broken visual grammar). font-family family signatures are intentional and must be preserved. Next recommended: extend --space-4 to non-warm-paper :root blocks as shared spacing vocabulary.
