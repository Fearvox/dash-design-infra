Naming inconsistency is the more addressable finding than the 4px padding delta.

F2 Proportionality test: does padding track chrome scale?

Two Pattern B surfaces use .shell with grid rows for chrome bars (top + foot). Test: is the 4px padding delta proportional to the chrome scale?

Surface Padding Chrome (top + foot) Padding / chrome ratio Classification
motion-storyboard 40px 104px (66+38) 0.385 Higher ratio — tighter padding relative to chrome
prompt-dna-adapter 44px 152px (96+56) 0.289 Lower ratio — looser padding relative to chrome

Conclusion: The proportionality hypothesis is inverted. motion-storyboard has a higher chrome-to-padding ratio (0.385) than prompt-dna (0.289). The 4px padding delta is not proportional to chrome scale — it is a deliberate design choice, but the rationale is not "padding matches chrome size."

Alternative explanation: motion-storyboard's inner content is 6 story-frame thumbnails (small visual elements, tight inner spacing), so a tighter 40px shell padding creates more breathing room for the content grid. prompt-dna's inner content is dense prompt text + a parameter panel, so a 44px shell padding creates more white space for reading. The 4px delta may be intentional, tuned to content density rather than chrome size.

F4 Naming inconsistency — the addressable finding

Four CSS class names serve the same conceptual role (the inner content container in Pattern B). Token-level alignment is impossible while names differ:

Class name Surfaces Same role? Re-nameable to .shell?
.shell motion-storyboard, prompt-dna-adapter, social-card Yes (inner container) n/a (already canonical)
.poster-frame poster-surface Yes (same role, decorative rounded frame) Possible — rename to .shell + apply border-radius: 44px separately. Preserves the rounded aesthetic.
.capsule frontier-capsule No — the capsule itself is the visible card, not a content card inside a page. Different role. Do not rename. The capsule is the page's primary visual artifact.
.sheet pdf-zine No — the sheet is a print-page artifact with 6 panels. Different role. Do not rename. Print sheet has a fundamentally different structure.

Conclusion: .poster-frame is the only renamable variant. Three of four names refer to genuinely different roles. Renaming .poster-frame to .shell + applying the decorative border-radius separately would unify the inner-container naming and make a future --pad-shell token apply uniformly.

F5 Token layer opportunity — design-decision-blocked

Based on F1–F4, three token candidates could be proposed:

  1. --pad-shell: 44px — align inner container padding across all Pattern B surfaces. Visual delta: motion-storyboard +4px (40→44). Closes the 4px drift pair. Requires a design call on whether motion-storyboard's 40px is intentional tight padding for 6-frame content or accidental drift.
  2. .shell class unification — rename .poster-frame to .shell + apply border-radius: 44px via a --shell-radius companion token. Unifies the 3-surface naming. Purely cosmetic, low risk.
  3. --pad-page: 56px — already shipped (PR #156, 2026-06-06). 4 of 4 warm-paper Pattern A consumers aligned. No further work needed.

Decision blocker: introducing --pad-shell requires a creator/design verdict on whether motion-storyboard's 40px is "tighter padding for thumbnail-grid content" (intentional, retain) or "leftover from a pre-token layer" (drift, align). The visible difference between 40px and 44px is ~0.4% of canvas width on a 1684px-wide page — the visual change is subtle but real.

Recommendation: hold --pad-shell tokenization. Apply only the low-risk .shell class-unification mutation (rename .poster-frame to .shell on poster-surface) as the next atomic slice. This unifies naming without changing padding values — a smaller, lower-risk step toward aesthetic coherence.
